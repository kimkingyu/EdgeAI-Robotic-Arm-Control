### 📍 阶段 1：端侧 NPU 模型量化与推理加速专项【实测完成 ✅】
> **核心目标**：彻底压榨 RK3588 6 TOPS NPU 算力，量化压缩视觉模型并实现高吞吐并发推理。  
> **全部数据均由板端真实跑出**，详见 [`docs/benchmarks/NPU_BENCHMARK_REPORT.md`](benchmarks/NPU_BENCHMARK_REPORT.md)。

- [x] **1.1 板端原生工具链搭建（推翻双机方案）**：
  - 探测发现 `rknn-toolkit2` 自 2.x 起已提供 **aarch64 原生 wheel**，遂放弃"x86 PC 转换 → 板端部署"的双机流程，改为**香橙派自转自跑单机闭环**；
  - 板端安装 `rknn-toolkit2 2.3.2`（含 torch 2.2.0 / onnx 1.16.1，`onnxoptimizer` 现场编译 aarch64 wheel）；
  - 推理运行时 `librknnrt.so` 由 **0.9.6 (2023) 升级至 2.3.2 (2025)**，旧版备份为 `librknnrt.so.bak_0.9.6`。
- [x] **1.2 INT8 训练后量化 (PTQ) 导出**：
  - 构建 COCO128 真实场景 100 张校准集（`data/calibration/`）；
  - 逐通道非对称 INT8 量化，**YOLOv8n: 12.2MB → 4.73MB（压缩 61.2%）**，YOLOv11n: 10.4MB → 4.54MB；
  - 攻克三处硬伤：`opset 20/22 超出 RKNN 上限 19`、`校准集路径二次拼接导致解码失败`、`YOLOv11 动态形状无法量化`。
- [x] **1.3 算子硬件亲和力实测（结论与预期相反）**：
  - 逐算子解析构建日志 `Target` 列，**YOLOv8n 直通率 97.46%（115/118）**，**YOLOv11n 98.75%（158/160）**；
  - 二者纯计算算子均 **100% NPU 执行、零真实回退**，`Conv+SiLU` 被融合为 `ConvExSwish` 单算子；
  - v11 的 C3k2 + PSA 注意力在 RKNPU 2.3.2 上已被完整支持，直通率反优于 v8；但算子数多 35.6%（160 vs 118），**端到端耗时高 17.2%**，故仍选定 **YOLOv8n 为实时伺服主干**。
- [x] **1.4 系统级调频优化**：
  - 定位瓶颈：NPU 全程满频 1GHz、温度仅 46℃，真正卡点是 **CPU 侧的输入拷贝与输出反量化**被 `ondemand` 压在 1.2GHz；
  - 交付 `scripts/set_performance.sh`（CPU/GPU/NPU/DDR 全线锁频 + 大核绑定）；
  - 实测收益：单帧 **29.60ms → 23.23ms（-21.5%）**，P99 抖动 **±5.94ms → ±0.65ms（-89%）**。
- [x] **1.5 三核真并发推理池（关键突破）**：
  - 实测证伪"`core_mask=NPU_CORE_0_1_2` 即可多核加速"，因 `inference()` 同步阻塞，单实例三核仅 **1.03x**；
  - 重构 `src/inference/rknn_engine.py`，新增 `RKNNParallelVisionPool`：**每核心独立 RKNNLite 实例 + 多线程任务队列**；
  - 实测 **3 路并发 2.71x 近线性加速（38.5 → 104.5 FPS）**，单路时延仅增 7%；生产封装实跑 **112.99 FPS**。

**阶段成果**：单路实时检测 **44.24 FPS / 22.61ms**，系统峰值吞吐 **112.99 FPS**（可支撑 3 路工业相机），P99 抖动 ±0.65ms 满足伺服控制确定性要求。

- [ ] **1.6 待办：DMA-BUF 零拷贝与量化精度验证**：
  - 接入 Linux DMA-BUF 内存共享通道，消除 CPU 侧图像搬运开销；
  - 相机到货后用真实工件数据集验证 INT8 量化的 mAP@0.5 精度损失。

### 📍 阶段 2：端侧具身大模型 (Qwen) 与端云协同调度【架构就绪 🧠】
> **核心目标**：实现无网/弱网环境下 100% 离线自主意图解析与 Function Calling 结构化任务流规划。

- [x] **2.1 工业 Prompt 工程与动作状态机设计**：
  - 编写 `src/llm/planner.py`，基于 Qwen 原生 `<|im_start|>` 格式规范输入与纯 JSON 输出格式；
  - 定义 `pick`、`place`、`inspect`、`move_safe` 与 `emergency_stop` 五大核心原子动作。
- [x] **2.2 典型工业多工况测试用例集**：
  - 编写 `tools/test_qwen_function_calling.py`，覆盖标准工步、连续码垛、安全急停、模糊意图等 5 大典型场景；
  - ⚠️ **此前记载的"遵循率 100%、耗时 120.9ms"已证伪**：板端未装 rkllm，引擎静默走 Mock 分支，该数据实为 `time.sleep(0.12)` 与规则引擎关键字匹配的产物，不代表模型能力。已修正为 Mock 模式强制告警，详见 [`QWEN_DEPLOYMENT_BLOCKER.md`](QWEN_DEPLOYMENT_BLOCKER.md)。
- [x] **2.3 端云协同自适应分发与断网无感降级**：
  - 编写 `src/llm/cloud_api_client.py` 与 `src/llm/hybrid_router.py`，构建混合路由体系；
  - 运行 `tools/compare_cloud_edge.py` 完成三模态全景 Benchmark 测试。
- [x] **2.5 Qwen3-VL-4B 视觉多模态板端部署【已跑通 ✅】**：
  - 选定路径：放弃板端量化，采用社区现成 **Qwen3-VL-4B-Instruct w8a8**（语言 4.51GB + 视觉 0.81GB）；
  - 升级 `librkllmrt.so` v1.0.1 → **v1.2.3**（旧版备份可回滚），驱动 0.9.6 的告警实测不影响运行；
  - 用 **ctypes 直接绑定运行时**替代官方 C++ 方案，结构体尺寸经实测校验（`RKLLMExtendParam`=120、`MultiModalInput`=48 全部吻合）；
  - **核心踩坑**：视觉编码器输出 4 个 deepstack 特征层，只取 `out[0]` 会导致首 token 后立即停止生成，必须拼接为 `(196, 10240)`；
  - **真实实测**：TTFT 253ms（纯文本最优）/ 6.32 tok/s / JSON 遵循率 100%，视觉抓取决策能给出基于物理属性的推理；
  - 完整数据见 [`QWEN_VL_BENCHMARK_REPORT.md`](benchmarks/QWEN_VL_BENCHMARK_REPORT.md)。

- [ ] **2.4 W4A16 量化【受阻 ⛔，已由 2.5 的 w8a8 方案绕过】**：
  - **硬约束**：`rkllm-toolkit` 官方从 v1.0.1 到 v1.3.0 **只发布 `linux_x86_64` wheel，无任何 aarch64 版本**（已通过 GitHub API 核实全部 4 个 wheel）。与阶段一的 `rknn-toolkit2` 不同，**板端无法自转自跑**；
  - **次生约束**：板端 `librkllmrt.so` 为 v1.0.1（2024-05，早于 Qwen2.5 发布），头文件仍是旧的 `_LLM_H_` 接口；社区现成模型均由 toolkit v1.2.x 转换，需先升级运行时（v1.2.3 要求 RKNPU 驱动 0.9.8，板端为 0.9.6）；
  - **可行路径**：① 部署社区现成 W8A8 模型（已验证 hf-mirror 可达，1.5B 约 2.05GB）；② 借 x86_64 Linux 主机自行量化；③ 暂缓，先推阶段四；
  - 完整调研与决策依据见 [`QWEN_DEPLOYMENT_BLOCKER.md`](QWEN_DEPLOYMENT_BLOCKER.md)。
